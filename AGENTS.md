# AGENTS.md

**HomeOps** — локальная домашняя лаборатория для роли **DevOps / Platform Engineer** со специализацией ML/AI-платформа: от первых стендов по Linux и Docker до платформенной инженерии. Языки программирования лаборатория не учит. Это учебная лаборатория, а не подготовка к найму: экранов собеседования, резюме и откликов не добавлять. Профили требований составлены по анализу открытых вакансий в России и за рубежом (осень 2026). Основной профиль — `platform-engineer` (`DEFAULT_VACANCY_ID`), `mlops-ai-platform` — специализация. **Никакого ложного прогресса:** зачёт только за подтверждённую практику.

Читателю — [README.md](README.md), стенды — [incidents/README.md](incidents/README.md), автопрогон — [scripts/README.md](scripts/README.md), Windows — [WINDOWS.md](WINDOWS.md), измеренные модели — [scripts/models/README.md](scripts/models/README.md).

## Работа и карта кода

- Node 22.18+: `npm install`, `npm run dev` (порт `:5173` и API файлов), `npm test`, `npm run check` (проверка типов → линтер → тесты → сборка).
- После правок кода или данных пересобрать локальный дашборд: `docker compose up -d --build` (дашборд на `:8080`, сервис стендов на `:8091`), проверить оба `/healthz`.
- `src/data/` — только исходная программа: `curriculum`, `skills`, `roles`, `resources`, `labSteps`, `quizzes`, `drills`, `incidents`, `interview`, `exercises`; конструкторы — `builders.ts`, расширения — `packs/`.
- `src/lib/` — чистая логика с `*.test.ts`; `src/state/` — reducer всех изменений, `StoreProvider` и hash-router; `components/` и `pages/` — тонкий UI.
- `src/config/weights.ts` — веса и пороги: `TASK_KIND_WEIGHT`, `TASK_KIND_LEVEL`, `IMPORTANCE_SHARE`, `IMPORTANCE_ACTION_WEIGHT`, `PRIORITY_SCORE`, `TRACK_ORDER_PENALTY`. Не хардкодить их в логике; тесты инвариантов не ослаблять.
- `server/` — Node без npm-зависимостей, только стираемый TypeScript (без `enum`, `namespace`, свойств параметров конструктора). `progressApi.ts` — файл, ревизии и снимки; `incidentReports.ts` — входящие отчёты; `contentIssues.ts` — замечания; `serve.ts` и `labsProxy.ts` — статика и прокси; `labs.ts` и `labs-serve.ts` — сервис Docker; `websocket.ts` — терминал; `requestGuards.ts` — проверки `Host`, `Origin`, JSON и лимитов.
- `incidents/<id>/` — Compose, проверки, исходные файлы `.original/` или серверный `setup/`; `_tools/` — проверка, сброс и помощники; `_shared/` — образы и учебные сервисы. **`data/` — данные пользователя.**

## Данные и зачёт

- Программа и прогресс разделены: **id нельзя переименовывать или переиспользовать** (задачи, навыки, ресурсы, вопросы). Текст критерия приёмки — ключ отметки; менять только осознанно. id вопросов — ключ статистики.
- Задача засчитывается при статусе «Выполнено», всех критериях и подтверждении; чтению подтверждение не нужно. Тест — только полная попытка (`QUIZ_SIZE`) со счётом ≥ 80% через `quizAttemptPasses`; `passed` не доверять. Ручного статуса недостаточно.
- Навыки: чтение и тест дают максимум 1, упражнение и лабораторная — 2, интеграция — 3 (переопределение — `grantsLevel`); решённый стенд даёт своим `skillIds` 2 самостоятельно и 1 после разбора (`INCIDENT_LEVEL`); 4 — реальный production через самооценку с текстовым обоснованием. Текущий уровень — максимум подтверждённого и обоснованного заявленного, с исходным профилем.
- Обучение — взвешенная доля засчитанных основных задач; `optional`, `fundamentals`, `advanced` и заблокированные задачи с зависимостью от окружения исключены. Веса типов: чтение — 1, тест и упражнение — 2, `lab` — 4, `integration` — 6; источник — `weights.ts`.
- Покрытие профиля (страница «Навыки») считается отдельно: `min(current,target)/target`, среднее внутри категории; `Required`, `Important`, `Bonus`, `Advanced` = **70/22/8/0**. Желательные ограничены своей долей, `Advanced` оценку не повышает.
- Задача с зависимостью от окружения в статусе «Заблокировано» исключается из прогресса и не блокирует зависимые; обычное «Заблокировано» блокирует. Основные задачи не зависят от `fundamentals` и `advanced`; циклы запрещены.
- Следующие действия — доступные незасчитанные основные задачи: приоритет, бонус «В работе» и разрыва роли, штраф `TRACK_ORDER_PENALTY` за `order` трека. «Выполнено без подтверждения» выше остальных. Порядок треков рекомендательный, `prerequisites` — ограничения: сначала платформенная база (K «IaC и GitOps», затем A), потом специализация ML/AI-платформы в порядке зависимостей — CI/CD (G) и наблюдаемость (D) построены вокруг LLM-сервиса. Для `platform-engineer` весь K идёт раньше задач специализации (тест). Независимое чтение ради разрыва роли может идти параллельно текущему треку; `NextAction.why` объясняет выбор через `InfoTip`.
- `workProblem`, `entryRequirements`, `learned`, `nextSteps` — описания трека; связи карты — `prerequisites` задач. Итог трека — когда все обязательные задачи засчитаны; 100% с исключениями окружения не заменяет зачёт.
- Инцидент решён, если **все текущие `checks`** описания пройдены; `passed` и `solvedAt` не доверять. Отчёты до `meta.createdAt` отвергаются. Разбор до решения означает «с разбором». Статусы и уровни навыков через `confirmedIncident` и `incidentStatusFor`, второго расчёта не создавать. Инциденты не повышают обучение (долю задач); роль — только через `skillIds` и `INCIDENT_LEVEL`.
- Формат `homeops-progress` (`FILE_FORMAT`, `EXPORT_FORMAT`) и префикс `homeops` (localStorage, метки, образы) **не переименовывать**: это совместимость файлов, кэша и ресурсов.
- Источник истины — `data/progress.json`; localStorage — кэш. Запись атомарная (временный файл и `rename`); снимки ежедневно, перед импортом и сбросом, последние 60 — в `data/backups/`. Compose монтирует `./data` по умолчанию; файл общий с dev-сервером. `DASHBOARD_DATA=homeops-data` выбирает именованный том: dev-сервер получит другие данные, `down -v` или сброс Docker удаляет том. Повреждённый файл не перезаписывать. Экспорт и снимок импортируются с нормализацией и проверкой версии. Перед заменой сохранить и несохранённые правки; без копии замена запрещена (при недоступном API — скачать копию).
- Кэш пишет файл только при несохранённых правках поверх **той же ревизии** (`homeops.sync.v1`); конфликт сохраняет локальные правки снимком и загружает файл. Не сравнивать версии по времени и не возвращать хранение только в браузере. `progressRequest.ts` ограничивает `fetch` **и тело**; таймаут сохраняет очередь, ревизии, снимок. Фоновый запрос — 10 с, повтор записи — 15 с.
- Нормализация и импорт даты не придумывают: записи без дат сохраняются, но не входят в активность и сроки. `tasks[id].timing` — первое новое «В работе» и первый зачёт; повторный зачёт длительность не переписывает. `taskEstimates.ts` — ориентиры сложности и времени, не зачёт.
- Дневника нет: заметки — в задаче. Поле `progress.journal` сохраняется в типах, нормализации, экспорте и снимках ради совместимости файлов; строка на «Резервной копии» — только при записях.
- `measurements` и `ckaExams` необязательны; не создавать пустые поля в прогрессе, где их не было. Диагностика не пишет даже статистику и попытки; конспекты, шпаргалки, шаги, асинхронные викторины и тур ничего не засчитывают. Подсказки не меняют зависимости; тур использует только localStorage.
- `confirmedState` только читает прогресс, без очков и серий. Зачёт через `getVerification` и текущие `checks` инцидента; самостоятельность — до разбора; зал — полная сессия по порядку. Отмена подтверждения снимает результат. События — сохранённые даты (практика — первое подтверждение засчитанной задачи), не `updatedAt`.

### Данные пользователя и QA

**Не удалять и не перезаписывать `data/` без явной просьбы.** Проверки — в своём preview с временным `DATA_DIR` и подставным API прогресса и экзамена. После проверки удалить только свои данные и сообщить об этом.

`verify` отправляет отчёт в работающий дашборд: `data/incident-reports.json` → `progress.incidents`. Свои прогоны — **`DASHBOARD_URL=off`**, например `docker compose run --rm -e DASHBOARD_URL=off verify`; кнопка и API `verify` пересылают всегда. Не запускать стенды, которые уже работают в дашборде. Если попал тестовый отчёт: убрать его и записи `incidents` через `PUT` с актуальной ревизией, сразу вызвать **`location.reload()`** во вкладке (hash-навигации недостаточно), иначе старый кэш создаст конфликт и снимок с тестовыми решениями.

«Есть проблема» хранится в `data/content-issues.json`. Разобрать `open` при работе над программой: исправить по правилам контента без смены id, изменить только `status=fixed/wontfix`, `resolution`, `resolvedAt`. Это единственное исключение для `data/` без отдельной просьбы; прямой запрет пользователя читать или менять `data/` важнее. Для автопроверки лабораторных JSON и `source:auto` не доказывают происхождение; нормализация не доказывает практику и не защищает от обмана. Нужна граница доверия восстановленных записей и доверенных отчётов.

## Контент

- Всё по-русски; устоявшиеся технические термины не переводить. Меню из 6 пунктов: Сегодня; Учиться (Дорожная карта — вкладки «По трекам», «Таблица», «Тесты»; Материалы — вкладки «Материалы», «Конспекты и шпаргалки»); Практика (Стенды — вкладки «Инциденты», «Залы»; Тренажёр — вкладки «Тренажёр», «Своими словами», «Проектирование»); Прогресс (Навыки, Резервная копия). Новое — вкладка существующего раздела, не новый пункт меню; лишнее убирают целиком, а не прячут.
- Глоссарий: «Не начато / В работе / Выполнено / Заблокировано», «Обязательное / Важное / Желательное / Продвинутое», «критерии приёмки», «предыдущие задачи», «трек».
- У каждой основной задачи должен быть русский материал (тест). Официальный **перевод текста**, не только меню, — `ru` ресурса (RU · EN); отдельные русские материалы — ШАД, хендбуки, инженерные и корпоративные статьи Хабра, без SEO. Официальный EN — свёрнутый справочник. Новую ссылку проверять: HTTP 200 после перенаправлений, канонический URL и тематический `<title>`; Хабр с ответом 403 не добавлять.
- Практика основных треков — план `labSteps.ts` из ≥ 4 конкретных шагов: файлы и папки `ai-platform-labs`, команды, параметры, проверки, подтверждения. `isPracticeTask` включает `exercise`, `lab`, `integration` везде (поиск, Сегодня, навыки).
- Тесты: уникальный id, ≥ 3 различных вариантов; `correct` — индексы (несколько — множественный выбор), `explanation` объясняет почему. Последний аргумент `q(...)` — `notes` **каждого неверного** по порядку; у правильного `optionNotes` пусто. Объяснять заблуждение, не писать «неверно». Около 36–40 вопросов на трек, понимание, не память API; апостроф в одинарных строках экранировать `\'`.
- Ответ нельзя угадать по форме: правдоподобные отвлекающие той же формы и длины; правильный короткий, обоснование в `explanation`, без пустых «Ничем», «Не нужно», «Одно и то же». В множественном выборе есть неверный. Тест длины: правильный ≤ 1,3× самого длинного неверного; по банку ≤ 35% вопросов, где он самый длинный или короткий. **Не ослаблять**, переписывать варианты.
- Банки повторения: те же правила и `notes`, ≥ 40 вопросов на тему, без повторов по тексту; id начинается с id банка. `area`: `ml` (`ml-*`), `infra` и `data` (`dv-*`); группы `DRILL_AREAS` и `DRILL_GROUPS` в `drills/areas.ts`, подписи `drillLabel`. Пустые группы скрыты. `qo(id,text,output,…)`: реалистичный вывод, ответ следует из него, `notes` ссылаются на строки. У всех Kubernetes-вопросов CKA-домен в таблице CKA в `k8s.ts` (тест). Банки не повышают обучение и роль.
- «Своими словами» (данные `interview.ts`, страница `interview`): 8–10 вопросов на тему, 3–6 ключевых тезисов и типичная ошибка; id — ключ оценки. `skillIds` вопроса (подмножество темы) обязательны при нескольких навыках; каждое требование профиля кроме `advanced` имеет вопросы, `required` ≥ 3 (тест). `group` — `devops` или `mlops`, явные `incidentIds` — стенды по теме.
- Шкала самопроверки: 0 «Не могу ответить», 1 «Отвечу с подсказкой», 2 «Объясню самостоятельно». Оценка 3 из ранней версии шкалы хранится в файле и читается как 2 (`explainRating`). Оценка вслепую, сверка с тезисами, переоценка, срок повторения по оценке; `blind` отдельно от `after-check`, сохранённые оценки и даты не переписывать. На обучение, навыки и покрытие профиля не влияет.
- Проектирование (`systemDesign.ts`): 7 аспектов, ≥ 3 вводных (нагрузка, SLO, ограничения), ориентир каждого аспекта из ≥ 3 тезисов и типичные ошибки (тест). Сначала собственный ответ, затем разбор; `blind` отдельно от `after-check`, самопроверка ничего не засчитывает. `exerciseId` связывает схему, предлагается **после** сверки, чтобы не подсказать ответ.
- Упражнения: `order` — 4–8 однозначных шагов; `match` — ≥ 3 пары **и лишний справа**; `error` — строки, индексы и исправления, одна правка на строку без равноценных решений; `arch` — вводные, 2–5 слоёв по запросу, 8–14 блоков, 2–4 правдоподобных вредных лишних той же длины, `note` каждого. Блок однозначно в одном слое, иначе переформулировать. Всегда разбор почему; id с префиксом набора — ключ статистики. Не повторять причину и исправление инцидента; форму проверяет `exercises.test.ts`.

### Расширение программы

Большой блок — в `src/data/packs/<name>/`, не в базовых файлах: `pack.ts` (`ContentPack`: треки, задачи, навыки, `requirements`, `resources`, `interview`, `interviewExtras`, оценки), `quiz.ts`, `steps.ts`; подключить `packs/index.ts`, `quizzes.ts`, `steps.ts`. Общие конструкторы и тесты. Инциденты остаются в `incidents.ts` (читает плагин сборки); менять коротким шагом и коммитить с папкой стенда.

Трек: `id`, `code`, `title`, `goal`, `kind(core|fundamentals|advanced)`, `order`, `topics`, `acceptanceCriteria`. Задача: новый `id`, `trackId`, `kind`, `priority`, `prerequisites`, `resourceIds` с RU, `acceptanceCriteria`, `vacancyRequirementIds`, план; при необходимости — `optional` и `environmentDependency`. Роль: `skills` и `vacancies` с `title`, `summary`, `platform`, `responsibilities`, `requirements(skillId,importance,targetLevel,summary)`; `company` только для конкретной вакансии. Задачи и стенды связаны навыками со всеми ролями. Навык входит в профиль вместе с вопросами «Своими словами» и практикой — задачей или стендом с этим навыком (тесты). Поднять `CURRICULUM_VERSION` (`src/data/index.ts`); тесты ссылок, уникальности, циклов. Модели и квантизации добавлять в планы после физического замера и проверки происхождения; обучение и multi-LoRA требуют отдельных результатов.

## Стенды и залы

Проверенные конфигурации: Mac на Apple Silicon — CPU arm64 в Docker, Metal нативно или через DMR; Windows 11 и WSL2 с NVIDIA 8 ГБ — GPU, проект внутри WSL. Мультиархитектурные образы amd64 и arm64; инструменты в контейнере, не полагаться на хостовые `bash` и `curl` (Windows — PowerShell). Проверенные профили и ограничения — в `WINDOWS.md` и `scripts/models/README.md`.

- Стенды, которые контейнер не воспроизводит честно (зомби-процессы и SIGCHLD — исправление в коде родителя; смена часов и NTP — нужна виртуальная машина), не делать.
- Проверять **итоговое состояние**, не способ решения: HTTP, метрики, код возврата. Ошибка описывает симптом и цель без решения; сценарий — без причины, подсказки — от направления к конкретике, разбор — причина, исправление и вывод.
- До завершения проверить сломанное, все частичные и исправленное состояния, обходы **каждого** ограничения, ожидаемые результаты всех id; потом `reset` и `down`. id `checks` совпадают с описанием (тест). Ограничения в `constraints`, не в цели; каждое реально ловится (исходные файлы, UID, конфигурация), иначе обещание не подтверждено.
- Монтировать папки, не отдельные файлы (атомарное сохранение в редакторе меняет inode). Правимые файлы в `.original/`; если добавленный файл даёт обход (`conftest.py`, `ruff.toml`), папку перечислить в `.original/.exact` для точного восстановления с удалением добавленного.
- Категории: `mlops` с `trackId`; `devops` с `topic`, не входят в учебный прогресс. CI/CD без сети: `homeops-ci-python`, пакеты в `/wheels`, `no-index` в `/etc/uv/uv.toml`; новые пакеты в `Dockerfile`, пересобрать с PyPI заранее.
- Терминал Compose — `shell`: метка `homeops.terminal` описывает реальные инструменты, `working_dir` внутри `/scenario`. `compose run -d shell sleep 86400` требует `entrypoint`, выполняющий переданную команду; `["bash"]` превратит её в `bash sleep` и сломает запуск.
- Сервер: `server: true`, `homeops.role: server`, Ubuntu с systemd из `_shared/linux-server`, **без `privileged`**: `SYS_ADMIN` и `cgroup: private`, `homeops-init` перемонтирует cgroup2 на запись. Не монтировать `/sys/fs/cgroup` хоста (WSL: код выхода 255, `init.scope`). При первом старте — `setup/setup.sh`, затем `setup` отмонтируется. В сервер монтировать только `setup`, `_tools`, `checks.py`, `.reports`, не весь стенд. Терминал — `bash -l`, `verify` внутри, `reset` пересоздаёт сервер.

### Kubernetes

- `cluster: true`, `topic: Kubernetes`, `homeops.role: k8s`: общий kind **`homeops`**, kubeadm с control-plane и worker (~850 МБ пустой). Namespace стенда `K8S_NAMESPACES` явно заданы в манифестах, не пересекаются (тест). Рабочее место — `kubectl`, подготовка — `.setup/setup.sh`, healthcheck → `up --wait`, сброс — `reset` и пересоздание рабочего места. Домены CKA — `cka`.
- Не менять общие taints и метки без возврата в `teardown.sh`. ClusterRoleBinding, PV с Retain, StorageClass переживают namespace: сброс удаляет по признаку стенда (`subject` или `claimRef` его namespace). NetworkPolicy проверять **из пода** (`pod_probe`, `exec` и Python), не через прокси API с узла; права — `can_i` с impersonation ServiceAccount.
- Образы приложений — `_shared/k8s/images.txt`, импорт по архитектуре: `docker save --platform` → `ctr`. `nodeAccess: true`, `homeops.cluster: exclusive` (тест) ломает узлы: только один стенд, запуск при других Kubernetes-стендах отклоняется и наоборот. `up` и `reset`: `cluster down` → `up` → `prepare id` → рабочее место; `down` удаляет кластер.
- Поломку узла готовят `.setup/node-control-plane.sh` и `node-worker.sh` через служебный `cluster`. `.setup/images.txt` загружается **до** скриптов; локальный `homeops-k8s-<name>` строится из `_shared/k8s/<name>/Dockerfile`. Исходное состояние (снимок etcd) создаёт скрипт узла через `admin.conf`, рабочее место — позже. Пересоздание ловить UID, сохранённым до поломки. Узловому стенду `manifests` и `.original` не нужны.
- `homeops-level setup` вызывает `teardown` перед `setup`; `teardown` у `nodeAccess` не откатывает поломку узлов (taint, метку, ресурс), иначе перезапуск рабочего места её снимет. Терминал `?node=control-plane|worker` только у запущенного эксклюзивного стенда. Состояние systemd узла (`enable`) проверять коротким подом с `nodeName` и `hostPath` только на чтение, только в полной проверке; под удалить после себя.
- MLOps в кластере (KServe): `category: mlops`, `trackId`, `cluster: true`, **без `topic` и CKA**, исключён из CKA-практики и экзамена. CRD, вебхуки, cert-manager и KServe требуют эксклюзивного `nodeAccess` со свежим кластером, локальных `images.txt` и архивов Helm в `.setup/charts/`, без сети.

### GPU

`requires: nvidia-gpu`, `homeops.requires`: без NVIDIA `up`, `reset`, `verify`, `check` и терминал отклоняются, `down` разрешён. Проба — фиксированная локальная `nvidia-smi`, без скачивания образа, сети и аргументов клиента, 20 с; таймаут **не кэшировать как отсутствие**. Пропуск по железу не считается прохождением. Одна GPU-нагрузка, заранее готовый физический кэш отдельно от замера. Бюджет CUDA не выводить из `nvidia-smi`: на проверенной WSL `util 0.90` не стартует (свободно ~6.93 из 8 ГиБ); измеренные профили — 0.5B BF16, 8K, 4 запроса, `util 0.35`; 3B BF16 и 7B AWQ, 8K, 2 запроса, `util 0.85` — в справочнике.

Живая проверка GPU — только чтение runtime, health и контракта: без генерации, ожидания, отчёта и зачёта. При `up` — постоянный служебный CPU-контейнер `homeops.live: gpu`, фиксированный `exec live python /tools/verify.py --live`; одна проверка стенда в полёте, параллельные получают её результат. Опрос контейнеров не создаёт. Настоящий inference — полный автопрогон с `DASHBOARD_URL=off`. Веса исключены из контекста сборки, фикстур и копирования; служебный контейнер **не получает GPU и не видит веса** (включая `/gpu/models` из общего монтирования, скрыть пустым `tmpfs` только на чтение). Канонический `.original/compose` должен содержать тот же служебный контейнер, иначе `reset` сломает опрос.

### Живые проверки и залы

`@check(...,live=True)` — только лёгкие проверки: без нагрузки, изменений и долгих таймаутов. `wait_deployment`, `wait_for`, собственные циклы при `kit.LIVE` делают **одну попытку**, иначе проверка только полная. Не удалять поды, не патчить ConfigMap, не убивать процессы. Живая проверка не пишет отчёт и не засчитывает инцидент.

Залы — `gyms.ts` и `incidents/gym-*`; сессия со сброса, id и порядок подходов совпадают с живыми `checks` (тест). Цепочка `needs`: поздний подход не ломает ранний, зачёт только текущего. «Найди факт» — ответ в `/answers/<name>`, сверка с **живым состоянием**; запоминаемый факт случайный при подготовке. Принимать все правильные способы (`envFrom`, `set env --from`). Залы не повышают обучение и роль.

Kubernetes: `.setup`, явные уникальные namespace, **общие узлы не менять**; MLOps-залы могут быть без CKA. Linux: `topic: Linux`, `homeops.role: server`, `setup/`. Compose: `homeops.role: compose-gym`, постоянный `shell` с healthcheck готовности и `.setup`, `DASHBOARD_URL: "off"`, фиксированный `exec shell python /tools/verify.py --live`; полная проверка и пересылка запрещены. При `reset` сначала остановить **только свой проект**; если `stop` не прошёл, не очищать метаданные. Восстановить исходные файлы и очистить учебные тома, ранее работавший зал вернуть через `up --wait`. Терминал — по своим меткам.

Airflow: живая проверка — только GET REST API v2 api-server с коротким таймаутом, без Airflow CLI, запуска DAG и ожиданий. Подготовка и ученик могут запускать DAG и backfill; timetable задаёт data interval, артефакт записывается атомарно по интервалу. Указывать измеренную память (на Mac standalone ~1,2 ГБ, запас 2 ГБ). LLM API: CPU, фикстуры без сети и весов, короткие синтетические HTTP-запросы; меняют лишь временные счётчики, не конфигурацию. Это не настоящий inference и не его замер. Учебные run и registry MLflow, запрос GPU и HPA без адаптера не доказывают обучение, GPU-inference и масштабирование. Python-тесты в `incidents/tests`: сломанное, каждое частичное и полное состояние.

### Экзамен и автопрогон

`ckaExams` — необязательная история в снимках конфликтов; балл по **полным отчётам `source:auto`** с текущими `checks`, после старта и текущего вызова `verify`; `passed` не доверять, живая проверка исключена. Попытка не повышает обучение, навыки и покрытие профиля; `verify` может засчитать инцидент. Автосдача продолжается при смене страницы, после закрытия возобновляется при открытии, просрочка видна. Проверки — только preview с подставным API без настоящего `verify`.

Фиксированный каталог автопрогона — 62 сценария, 311 этапов; новые отдельно (`scripts/README.md`). Копии Compose без портов хоста, `DASHBOARD_URL=off`, отдельный **`homeops-regression`**; каждый `nodeAccess` пересоздаёт только его. Литеральные имена узлов заменять только в копиях, рабочий `homeops` не трогать. При таймауте или отмене удалить именованный одноразовый контейнер **до `teardown`**, только при совпадении меток владельца, проекта и одноразовости; иначе сохранить и записать ошибку очистки. Отмена ждёт завершения CLI, очистка — без отменённого сигнала; `SIGKILL` и авария Docker не гарантируют очистку.

## Безопасность labs и HTTP

Сокет Docker даёт права администратора. Только фиксированные `up`, `verify`, `reset`, `down`, `check`, `logs`, `memory`, `terminal` над разрешёнными `incidents`, id и пресетами. `memory` — чтение Docker Engine API по метке compose-проекта. `check` — фиксированный `exec` в запущенном контейнере роли или служебном контейнере; **не принимать команду и аргументы клиента**. Кластер — только служебные `up`, `down`, `prepare id`, `images.txt` и скрипты узлов `.setup`; терминал узла только у запущенного эксклюзивного стенда из `CLUSTER_NODE_ROLES`. Сокет не давать рабочим местам. Таймаут Docker не откатывает операцию; она может завершиться после убийства CLI. Перед повтором обновить состояние.

Не снимать проверки `Host` (localhost и внутренние имена), **совпадения `Origin`**, `application/json` для POST, лимиты тела и запросов, привязку к `127.0.0.1`. При `isBaseImageUnavailable` запуск повторяет прежнюю команду без сборки на готовом образе, не новую произвольную команду.

Ориентиры HTTP (реализация — `server/*`): GET/PUT `/api/progress` (GET 404 до первого файла; PUT `{progress,baseRevision}`, 200 с `revision` или 409 с конфликтом); GET/POST `/api/backups`; GET `/api/health`; GET/POST `/api/incidents/reports` (входящие отчёты); GET `/api/labs/status`; POST `/api/labs/incidents/<id>/{up,verify,reset,down,check}`; GET `logs?service=` и `memory`; WebSocket `terminal`. Прокси соблюдает те же ограничения.

## UI и код

- Строгий TypeScript, React 19 и Tailwind 4; зависимости только по необходимости, сервер без зависимостей. Иконки — `lucide-react`. `.tsx` экспортирует только компоненты (`react-refresh`), константы и функции — в `lib`. React Hooks 7 запрещает синхронный `setState` в эффекте и внешние изменения при рендере; внешнее через `useSyncExternalStore`.
- Токены темы обязательны (`bg-surface`, `text-muted`, `border-line`, `text-ok/warn/bad/info/violet`, `bg-accent/10`), иначе светлая тема ломается. Визуальный язык: локальный Onest без сети, `text-sm` — 15 px, `text-xs` — 13 px; `PageHeader` с подписью раздела (`eyebrow`), `Card` с `shadow-card` без рамок; акцентный блок `rounded-2xl` и тонированные `border` и `bg`; главное действие — `Button primary/lg`; пояснения в `InfoTip`, единый цвет `FORMAT_TONE`, иконка списка — `h-9 w-9 rounded-xl`. Не собирать новые экраны рамками `border-line`.
- `select` через `field` (своя стрелка и отступ), без собственного `pr-*` и обхода `field`. При 375 px не должно быть горизонтальной прокрутки: `min-w-0` для сетки и flex, `truncate`; названия — `line-clamp-2 sm:line-clamp-none sm:truncate`, бейджи в подписи — `sm:hidden` / `hidden sm:flex`. Tailwind 4: переопределение через `!` (`whitespace-normal!`), `cx` только склеивает.
- Сегодня: главный шаг и один `recommendedDailyItem`, остальные — «Ещё практика · N» через `useLocalState`. Выбор стабилен в локальном дне, `due` и `active` раньше `new`, сделанное сегодня не рекомендовать. Счётчик — **единицы формата**, включая скрытые; пропуск и скрытие в настройках браузера не результат, дата инцидента из `confirmedIncident`.
- Основной маршрут — «засчитано N из M», вес и время в «Подробнее» или `InfoTip`; взвешенный процент и роль отдельны. Ленты активности, достижений, симулятора, журнала измерений и страницы «Подтверждения» нет; `measurements` сохраняются в данных. Перед тестами только диагностика и тренажёр. «Своими словами» — все темы и «Пора повторить»; оценка вслепую и после сверки.
- Ленивая загрузка: страницы, режимы, `TaskDrawer`, `SkillDrawer` через `React.lazy` и `AsyncContent` (Suspense, граница ошибок, сообщение после 10 с). Тяжёлый статический импорт в `App` или `Layout` возвращает его в стартовый чанк.
- Стартовый каталог **без смены формата данных**: `taskCatalogPlugin` подменяет только стартовые `labSteps` и `incidents` лёгкими представлениями; полные — в ленивых `TaskDrawer` и `IncidentsPage`, число подсказок и все проверки сохранены. `packMetadata` облегчает `pack.ts`, `exercises`, `systemDesign` через AST данных **без исполнения кода**. На старте остаются все id, зависимости, критерии, уровни, требования и поля расчётов; полные тексты — через `useContentStore` ленивых экранов. Новый статический потребитель требует проверок `needsFullContent` и `bundleBudget`.
- `bundleBudget`: **записанный окончательный** главный чанк ≤ 900 КБ; запрещены полные `labSteps`, `incidents`, `pack.ts`, `exercises`, `systemDesign` в графе его статических импортов. Банки и тесты — отдельные чанки `devops-infra-banks`, `devops-data-banks` (список файлов раздела `data` в `vite.config.ts`), `mlops-banks`, `track-quizzes`. Порог предупреждения Vite 1200 КБ **не повышать**.

## Известные грабли

- Vite может не заметить запись в `src/data` из скрипта: нет HMR, старые данные. Перезапустить dev-сервер.
- Docker Hub может обрывать загрузку образов (EOF), хотя `curl` хоста работает. Базовый образ дашборда заменяется через `NODE_IMAGE` на зеркало реестра; сетевые настройки пользователя автоматически не менять.
- Если dl.k8s.io недоступен из Docker, использовать `curl` хоста, опубликованный SHA и локальную сборку `FROM scratch` / `COPY` (`homeops-k8s-upgrade:v1.37.1`). Кэш образов сохранять; холодная загрузка образа или модели дольше 5 мин — таймаут Docker, не ошибка стенда. Подготовить кэш и повторить.
- В WSL отсутствующий каталог монтирования создаёт root: заранее `mkdir -p data` своим пользователем (UID 1000 у `node`), иначе `Permission denied`. Исправлять владельца только каталога проекта, без `chmod 777` и перезаписи данных.
- localStorage привязан к origin (`:5173`, `:8080`), файл общий. Скриншот может отставать на кадр: сверять DOM и кэш.
- Docker Desktop на Mac монтирует папки проекта через `fakeowner`: `test -x` отвечает «да» для файла 644, но запустить его нельзя. `docker-entrypoint.sh` postgres исполняет такой скрипт из `/docker-entrypoint-initdb.d` и падает с кодом 126, а в WSL тот же файл подключается через `source` и работает. Скрипты, которые образ запускает сам, коммитить с битом исполнения (`git update-index --chmod=+x`); тест `incidents.test.ts` это проверяет для initdb.
- Права, выставленные **из контейнера** (сброс через `shutil.copy`, `chmod`), Docker Desktop на Mac хранит в xattr `com.docker.grpcfuse.ownership` поверх хостовых: `chmod` на хосте контейнер не увидит. Снять атрибут `xattr -d com.docker.grpcfuse.ownership <файл>` или сделать `chmod` из контейнера; `.original` создавать обычным `cp` файла, не `cp /dev/stdin` (права 0400).
- `kind load docker-image` с containerd падает из-за чужой платформы без локальных слоёв; `homeops-cluster` использует `docker save --platform linux/<arch>` → `ctr images import`.
- Для labs обязателен buildx (`docker-cli-buildx`), старый сборщик не задаёт `TARGETARCH`; `Dockerfile` оставляет fallback `${TARGETARCH:-$(uname -m …)}`.
- Kubernetes 1.37: упавший контейнер в backoff имеет состояние `terminated`, не `waiting:CrashLoopBackOff`; `logs` — последний запуск, `--previous` — до него. Стабильность — `Ready` всё окно `watch_ready`, не `RESTARTS` (backoff до минут).
- Серверные файлы перечислены поимённо в `COPY` в `Dockerfile`: новый модуль дописать, иначе `ERR_MODULE_NOT_FOUND` (`dockerfile.test.ts`).
- Полный экран `TerminalWorkspace` — классы **той же DOM-ветки**, без портала или нового `key`; `key` только при переподключении. Правая панель — `xl:has-[[aria-modal=true]]:z-[60]`, иначе терминал под меню. До `WebSocket.close` обнулить `onopen`, `onmessage`, `onclose`; старое событие не меняет новую сессию.
